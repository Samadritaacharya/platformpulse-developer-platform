# Product Vision

## Vision

Enable internal engineering teams to create, deliver and operate services through a supported path that is discoverable, measurable and reliable without removing team autonomy.

## Problem

Developer-platform value is often weakened by fragmented setup instructions, repeated repository and CI configuration, unclear service ownership, inconsistent operability controls and disconnected feedback. Platform teams then spend capacity answering repeated questions instead of improving reusable capabilities.

## Target users

- New Backend Engineer
- Experienced Service Owner
- Platform / SRE Engineer
- Engineering Manager as a decision consumer

## Jobs to be done

1. Start a new service without reconstructing standard controls.
2. Understand who owns a service and how it should be operated.
3. Receive fast and understandable CI/CD feedback.
4. Find the supported workflow and current documentation.
5. Prioritise platform improvements using evidence and measurable outcomes.

## Product principles

- Make the supported path the easiest path.
- Treat developers as internal customers and partners.
- Prefer reusable capabilities over repeated manual support.
- Tie roadmap decisions to user and reliability outcomes.
- Keep product metrics transparent and explain trade-offs.
- Preserve engineering autonomy through sensible defaults, not rigid gates.
