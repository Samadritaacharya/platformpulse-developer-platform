# Personas and Developer Journey

## Persona 1: New Backend Engineer

**Goal:** Deliver a first service change confidently and understand the supported path.

**Pain points:** access ambiguity, outdated documentation, copied repository patterns, unclear pipeline failures.

**Success signal:** reduced time to first successful deployment and higher confidence in platform guidance.

## Persona 2: Experienced Service Owner

**Goal:** Deliver changes quickly while maintaining reliability and clear ownership.

**Pain points:** inconsistent configuration, fragmented health views, incomplete runbooks and unclear dependencies.

**Success signal:** lower lead time, lower change-failure rate and faster recovery.

## Persona 3: Platform / SRE Engineer

**Goal:** Create reusable capabilities and reduce repeated support demand.

**Pain points:** recurring setup questions, duplicated pipeline patterns, missing ownership metadata and inconsistent operability.

**Success signal:** higher golden-path adoption, lower support demand and improved catalogue coverage.

## Journey

| Stage | User need | Platform opportunity | Example metric |
|---|---|---|---|
| Join / Access | Know what access is required | Role-based onboarding checklist | Time to development-ready access |
| Create service | Start from an approved path | Golden-path generator | Time to runnable service |
| Configure repository | Avoid copied legacy setup | Versioned templates and metadata | Template adoption |
| Build and test | Understand failures quickly | Consistent CI feedback | Pipeline success and duration |
| Deploy | Reach an environment safely | Deployment defaults and checks | Time to first deployment |
| Monitor | Understand service health | SLO and signal overview | SLO attainment |
| Incident response | Find owner and first action | Runbook and escalation metadata | MTTR |
